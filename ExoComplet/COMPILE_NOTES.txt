📌 CORRECTION APPLIQUÉE
════════════════════════════════════════════════════════════════════════════

Tous les fichiers .cpp incluent maintenant:

    #define _CRT_SECURE_NO_WARNINGS

Cette directive désactive les warnings Microsoft Visual Studio concernant:
- fopen() → fopen_s()
- sscanf() → sscanf_s()
- strncpy() → strncpy_s()
- fread(), fwrite(), etc.

POURQUOI?
---------
Ce projet utilise volontairement les fonctions C standard classiques
pour l'apprentissage. Les fonctions _s sont des extensions Microsoft non
portables. Le code reste sûr car:

1. HexView : Contrôle de taille avec sizeof() sur tous les buffers
2. SafeReader : Validation stricte avec malloc() et vérification des retours
3. CryptFile : Lecture par blocs avec taille fixe définie

💡 NOTE PÉDAGOGIQUE
════════════════════════════════════════════════════════════════════════════

Les fonctions _s (secure) de Microsoft ne sont PAS standard C/C++.
Pour un code portable qui compile sur:
  - Windows (Visual Studio, MinGW)
  - Linux (gcc, g++, clang)
  - macOS (clang)

Il est préférable d'utiliser les fonctions standard avec validation manuelle.

C'est exactement ce que font ces exercices:
  ✓ Vérification de NULL après fopen()
  ✓ Vérification du retour de fread()/fwrite()
  ✓ Utilisation de sizeof() pour les buffers
  ✓ Utilisation de strncpy() avec '\0' forcé manuellement
